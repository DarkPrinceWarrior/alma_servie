# Требования к данным для детекции аномалий методом PaAno

## 1. О методе

**PaAno** (Patch-based Anomaly detection) — метод детекции аномалий во временных рядах, принятый на конференции **ICLR 2026** (Park & Kang, 2026). На бенчмарке TSB-AD он занял **1-е место** среди 48 методов, обойдя трансформеры и foundation-модели при этом оставаясь легковесным (0.3M параметров, ~7–13 секунд на датасет).

### Как работает PaAno

1. Временной ряд нарезается на короткие перекрывающиеся **патчи** (окна) фиксированной длины
2. Лёгкая 1D-CNN обучается **только на нормальных данных**: кодирует каждый патч в вектор-представление
3. Обучение использует **triplet loss** (похожие патчи — ближе, различные — дальше) и **pretext task** (предсказание, являются ли два патча последовательными)
4. Из нормальных патчей формируется **банк памяти** — набор эталонных представлений нормального поведения
5. При инференсе для каждого момента времени вычисляется **anomaly score** — косинусное расстояние до ближайших нормальных патчей в банке памяти
6. Чем больше score — тем сильнее текущий паттерн отличается от всего, что модель видела в нормальном режиме

### Ключевое свойство

PaAno работает с **локальными временными паттернами** — анализирует поведение внутри коротких окон (32–128 точек). Это делает его особенно чувствительным к резким локальным изменениям (скачки давления, вибрации, тока), но требует, чтобы данные были достаточно детализированы по времени.

## 2. Формат данных

### 2.1. Формат файлов

PaAno работает с **табличными данными** (CSV), где:
- Первый столбец — **timestamp** (метка времени)
- Второй столбец — **well_id** (идентификатор скважины)
- Остальные столбцы — **параметры телеметрии** (числовые значения)

```
timestamp,well_id,Давление,Температура,Вибрация X,...
2025-06-21 02:14:15,1123л,45.2,68.1,0.012,...
2025-06-21 02:14:30,1123л,45.3,68.1,0.011,...
```

### 2.2. Формат дат

**Обязательно: ISO 8601 — `yyyy-mm-dd HH:MM:SS`**

| Формат | Пример | Статус |
|--------|--------|--------|
| `2025-08-10 14:30:00` | 10 августа 2025 | **Правильно** |
| `10-08-2025 14:30:00` | 10 августа или 8 октября? | **Неоднозначно!** |
| `08/10/2025 14:30:00` | Зависит от локали | **Неоднозначно!** |

Формат `dd-mm-yyyy` приводит к критическим ошибкам: дата `10-08-2025` автоматически интерпретируется как **8 октября** вместо **10 августа**, сдвигая все данные на 2 месяца. Мы столкнулись с этой проблемой на реальных данных негерметичности НКТ.

### 2.3. Именование параметров

Названия параметров должны быть **одинаковыми** во всех файлах/скважинах. Если один и тот же параметр называется по-разному в разных скважинах — модель воспринимает их как разные каналы.

Пример обнаруженной проблемы:
- 4 скважины: `Давление на приёме насоса кгс/см²`
- 1 скважина (172г): `Давление на выкиде ЭЦН`

Это один и тот же физический параметр, но из-за разного названия пришлось добавлять маппинг переименования вручную.

## 3. Критические требования к данным

### 3.1. Равномерный шаг по времени (обязательно)

PaAno работает с **патчами фиксированной длины**, поэтому временной ряд должен иметь **равномерный шаг**. Если исходные данные записаны с неравномерным шагом (а на практике это почти всегда так — каждый датчик пишет со своей частотой), необходимо **интерполировать** все параметры на единую равномерную сетку.

Как мы это делаем:
1. Для каждой скважины находим **общий временной диапазон** — пересечение диапазонов всех параметров
2. Создаём равномерную сетку с нужным шагом внутри этого диапазона
3. Интерполируем каждый параметр на эту сетку линейно по времени
4. Результат: прямоугольная таблица без пропусков (NaN = 0)

### 3.2. Нет пропусков (NaN)

В итоговой таблице **не должно быть пустых ячеек**. Нейросеть не может обрабатывать NaN. Если параметр не имеет значений в каком-то интервале — его нужно интерполировать или заполнить.

### 3.3. Все параметры синхронизированы

Все столбцы (параметры) одной скважины должны соответствовать **одним и тем же моментам времени**. Если разные датчики пишут с разной частотой — именно поэтому нужна интерполяция на общую сетку.

## 4. Частота дискретизации (шаг сетки)

### Это самый важный параметр с точки зрения качества данных.

PaAno нарезает временной ряд на патчи длиной `w` точек. Каждый патч покрывает временное окно = `w × шаг`. Модель ищет отклонения **внутри этого окна**.

#### Правило: аномалия должна содержать достаточно точек внутри патча

| Шаг сетки | Длина патча (точек) | Временное окно патча | Мин. длина аномалии для обнаружения |
|-----------|--------------------|--------------------|-------------------------------------|
| 15 сек | 128 | 32 мин | ~2–5 мин (8–20 точек) |
| 2 мин | 64 | 128 мин (~2 ч) | ~10–20 мин (5–10 точек) |
| 15 мин | 64 | 16 ч | ~1–3 ч (4–12 точек) |

#### Наш опыт

- **Солеотложение** (медленный процесс, развивается часами/днями): шаг **2 минуты**, патч 64 = окно 128 мин. Результат: **8/8 обнаружено**.
- **Негерметичность НКТ** (быстрый процесс, резкие скачки):
  - Шаг 2 мин, патч 32 → **4/5** обнаружено (пропущена 9-мин аномалия = 5 точек)
  - Шаг **15 сек**, патч 128 → **5/5** обнаружено (та же 9-мин аномалия = 37 точек)

**Вывод:** для быстрых аномалий (негерметичность, обрыв) нужна высокая частота — 15–30 секунд. Для медленных (солеотложение) достаточно 1–2 минут.

#### Рекомендация по частоте записи

| Тип параметра | Минимальная частота записи | Идеальная частота |
|--------------|--------------------------|-------------------|
| Вибрации (X, Y, Z, XY, XYZ) | 15 сек | 5–10 сек |
| Давление на приёме | 15 сек | 10–15 сек |
| Токи, напряжения (фазные) | 30 сек | 15 сек |
| Выходная частота, мощность | 1 мин | 30 сек |
| Температуры (масло, приём) | 2 мин | 1 мин |
| Cos Ф, дисбалансы | 2 мин | 1 мин |

Если часть параметров записывается раз в 15 минут (как сейчас у некоторых скважин) — интерполяция на 15-секундную сетку создаёт **ступенчатый сигнал** вместо реальной динамики. Модель по-прежнему работает, но эффективность для этих каналов снижается.

## 5. Объём нормальных данных (до аномалии)

### Это второй критически важный фактор.

PaAno обучается **исключительно на нормальных данных** — он запоминает, как выглядит нормальное поведение, и потом ищет отклонения. Чем больше разнообразных нормальных паттернов модель увидит при обучении — тем точнее она отличает реальные аномалии от нормальных вариаций.

#### Минимальные и рекомендуемые объёмы

| Параметр | Минимум | Рекомендуемый | Идеальный |
|----------|---------|--------------|-----------|
| Длительность нормальных данных | 8 часов | 3–7 дней | 14–30 дней |
| Количество нормальных точек (15с) | ~2 000 | ~20 000–40 000 | ~80 000+ |
| Количество нормальных точек (2мин) | ~240 | ~2 000–5 000 | ~10 000+ |

#### Наш опыт: как объём данных влияет на результат

**Солеотложение** (1–6 месяцев данных, десятки тысяч нормальных точек):
- Обучение на богатом разнообразии нормальных режимов
- Результат: 8/8, три скважины обнаружены **до** начала аномалии

**Негерметичность НКТ** (1–4 дня данных, 2 000–11 000 нормальных точек):
- Модель видит ограниченный набор нормальных паттернов
- Результат: 5/5, но с задержкой 6 мин – 1.5 ч у части скважин

#### Проблема высокой доли аномалии

Если аномалия занимает бóльшую часть выгрузки, для обучения остаётся мало данных:

| Скважина | Всего данных | Доля аномалии | Нормальных точек | Результат |
|----------|-------------|---------------|-----------------|-----------|
| 5271г | 47.5 ч | 0.3% | 11 375 | Обнаружена за 1ч 41мин **до** начала |
| 524 | 42 ч | 42% | 5 825 | Обнаружена за 6 мин **до** начала |
| 1123л | 23.5 ч | 56% | 2 500 | Обнаружена через 6 мин после начала |
| 172г | 95 ч | 83% | 3 906 | Обнаружена через 1ч 21мин после начала |

Видна прямая зависимость: чем больше нормальных данных, тем раньше и точнее обнаружение.

#### Рекомендация

**Включайте в выгрузку как минимум 3–7 дней нормальной работы до начала аномалии.** Если аномалия длится несколько дней — выгрузку нужно начинать заблаговременно, а не за несколько часов до инцидента.

Также полезны данные **после** аномалии (когда оборудование вернулось в нормальный режим) — они тоже используются для обучения и увеличивают объём нормальных примеров.

## 6. Полнота набора параметров

### 6.1. Какие параметры нужны

PaAno — **мультиканальный** метод: он анализирует все параметры одновременно и ищет совместные отклонения. Каждый канал — это дополнительный сигнал для модели.

Текущий набор (26 параметров):

| # | Параметр | Важность для детекции |
|---|----------|---------------------|
| 1 | Давление на приёме насоса | Высокая — прямой индикатор негерметичности и солей |
| 2 | Выходная частота | Высокая — отражает режим работы насоса |
| 3 | Токи на фазах А, В, С | Высокая — изменение нагрузки |
| 4 | Выходной ток ПЧ | Высокая — суммарная нагрузка |
| 5 | Полная выходная мощность | Высокая — интегральный показатель |
| 6 | Активная выходная мощность | Высокая |
| 7 | Температура масла двигателя | Средняя — медленный отклик, но информативен |
| 8 | Температура на приёме насоса | Средняя |
| 9 | Вибрации (X, Y, Z, XY, XYZ) | Средняя–высокая — шум, кавитация |
| 10 | Линейные напряжения (AB, BC, CA) | Средняя |
| 11 | Фазные напряжения (Ua, Ub, Uc) | Средняя |
| 12 | Напряжение пост. тока ПЧ | Средняя |
| 13 | Cos Ф | Средняя |

| 16 | Дисбаланс напряжений | Низкая–средняя |

### 6.2. Параметр «Выходное напряжение ПЧ»

В данных негерметичности НКТ отсутствует параметр **«Выходное напряжение ПЧ»**, который есть во всех скважинах солеотложения. Если этот параметр доступен — добавьте его.

### 6.3. Единообразие параметров между скважинами

Все скважины **одного типа аномалии** должны содержать **одинаковый набор параметров** с **одинаковыми названиями**. Модель ожидает фиксированное число каналов.

## 7. Метки аномалий (ground truth)

### 7.1. Что нужно для каждой аномалии

| Поле | Формат | Пример |
|------|--------|--------|
| well_id | Строка | `1123л` |
| start_date | `yyyy-mm-dd HH:MM:SS` | `2025-06-21 10:32:00` |
| end_date | `yyyy-mm-dd HH:MM:SS` | `2025-06-21 23:42:00` |
| data_start | `yyyy-mm-dd HH:MM:SS` | `2025-06-21 02:00:00` |
| data_end | `yyyy-mm-dd HH:MM:SS` | `2025-06-22 02:00:00` |

- **start_date / end_date** — границы аномального интервала
- **data_start / data_end** — границы выгрузки данных для этой скважины

### 7.2. Точность меток

Метки не обязаны быть идеально точными по секундам — PaAno работает с патчами, которые покрывают окно в 30–120 минут. Но:
- Метка **начала аномалии** должна быть точна с погрешностью **не более 15–30 минут**
- Метка **конца** может быть менее точной, если аномалия продолжается до остановки скважины

### 7.3. Множественные аномалии

Если в одной выгрузке несколько аномальных интервалов — укажите каждый отдельно. Данные между аномалиями будут использованы как нормальные для обучения.

## 8. Структура предоставляемых данных

### Вариант А: Готовый CSV (предпочтительный)

Один CSV-файл на тип аномалии, с равномерным шагом:

```
timestamp,well_id,Давление на приеме насоса кгс/см²,Выходная частота,Ток на фазе А,...
2025-06-21 02:14:15,1123л,45.2,50.0,12.3,...
2025-06-21 02:14:30,1123л,45.3,50.0,12.3,...
...
2025-08-10 02:07:30,3509г,38.1,48.5,11.8,...
```

Плюс файл интервалов:
```
well_id,start_date,end_date,data_start,data_end
1123л,2025-06-21 10:32:00,2025-06-21 23:42:00,2025-06-21 02:00:00,2025-06-22 02:00:00
```

### Вариант Б: xlsx по скважинам (текущий формат)

Принимается, но требует предварительной обработки. Если используется этот формат:
- Даты — в формате ISO 8601
- Названия параметров — унифицированы
- Сводная информация с метками — в отдельном файле

---

## 9. Чек-лист перед отправкой данных

- [ ] Даты в формате `yyyy-mm-dd HH:MM:SS`
- [ ] Названия параметров одинаковы для всех скважин
- [ ] Набор параметров одинаков для всех скважин (26 или 27 столбцов)
- [ ] Нет пропусков в данных (или пропуски явно помечены)
- [ ] Нормальных данных до аномалии — минимум 3 дня (лучше 7–14)
- [ ] Частота записи быстрых параметров — не реже 30 секунд
- [ ] Метки аномалий предоставлены с точностью до 15–30 минут
- [ ] Файл сводной информации содержит start_date, end_date, data_start, data_end

## 11. Что можно улучшить при лучших данных

1. **Больше нормальных данных** (7–14 дней) → раннее обнаружение для всех скважин, не только для 524 и 5271г
2. **Более частая запись** медленных параметров (Cos Ф, дисбалансы с 15 мин → 1–2 мин) → все каналы информативны
3. **Добавить «Выходное напряжение ПЧ»** → 27-й канал для полноты
4. **Больше скважин** → статистически значимая оценка метода
5. **Данные по другим типам аномалий** (обрыв штанг, заклинивание, перегрев) → расширение области применения
