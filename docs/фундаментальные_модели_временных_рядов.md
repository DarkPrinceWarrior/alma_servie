# Фундаментальные модели временных рядов для детекции аномалий ALMA

> Аналитическая записка. Оценка применимости предобученных фундаментальных
> моделей временных рядов к задаче детекции аномалий на нефтяных скважинах.
> Дата: 2026-05-22. Источник правды — серверная копия `a100`.

## 1. Контекст задачи

Текущий рабочий пайплайн ALMA построен вокруг детектора `paano_global` —
кандидата в продакшен. Его устройство:

- общий (глобальный) энкодер `PatchEncoder` с нормализацией RevIN, обученный
  self-supervised на обучающих скважинах (`alma_service/shared_encoder.py`);
- локальный банк памяти на референсных данных каждой скважины;
- контракт входа `edge_hold` (краевое допадение коротких окон);
- статусы с учётом покрытия данными (coverage-aware);
- доменный слой принятия решения, который сплавляет нейросетевую оценку с
  физическими признаками для каждого типа аномалии:
  - `negermet` — резкое падение давления (ступенчатая сигнатура);
  - `pritok` — постепенный тренд давления;
  - `salt` — солеотложение, многоканальная ветвь с признаками мягкого датчика.

Завершает пайплайн единый слой детекции начала (`onset_detection.py`):
причинный CUSUM + EMA, калиброванный через `CausalThresholds`, с порогами,
подобранными Optuna/TPE только на обучающих скважинах.

Ключевое наблюдение: PaAno — это **детектор на новизне восстановления**
(reconstruction/embedding-distance), обученный на собственных данных скважин.
Он не использует никаких внешних знаний о динамике давления.

## 2. Рассматриваемые модели

| Модель | Тип | Размер | Задача | Лицензия |
|---|---|---|---|---|
| **Timer-S1** (THUML) | Декодер-трансформер, MoE | 8.3 млрд (0.75 млрд активных) | Прогнозирование, zero-shot | Apache-2.0 |
| **Toto-2.0-2.5B** (Datadog) | Patched-декодер, чередование time/variate attention | 2.5 млрд | Многомерное прогнозирование, zero-shot | Apache-2.0 |

## 3. Принципиальная пригодность

Timer-S1 и Toto — это **прогнозисты**, а не детекторы аномалий. Thoth — это
**ризонер**, тоже не детектор. Поэтому ни одна модель не подключается «как
есть» вместо PaAno. Аномалия строится поверх прогноза:

```
оценка аномалии(t) = отклонение факта(t) от прогноза модели(t)
```

Это естественно ложится на все три типа аномалий ALMA:

- `negermet` — резкое падение → большой одномоментный остаток прогноза;
- `pritok` — постепенный тренд → накопленный дрейф остатка;
- `salt` — отложение → совместное отклонение нескольких каналов.

> Уточнение по итогам эксперимента 9.2: для `negermet` это подтвердилось,
> а для `pritok`/`salt` гипотеза «накопленного дрейфа остатка» в zero-shot
> **не подтвердилась** — см. раздел 9.2.

Toto и Timer-S1 выдают **вероятностный прогноз** (9 квантилей). Это даёт
калиброванный коридор: выход факта за квантильную полосу — естественная,
безразмерная оценка аномальности, не требующая ручной нормировки.

Это не наша гипотеза, а консенсус практиков: TSFM прогнозируют ожидаемое
поведение и **не являются детекторами аномалий** — слой детекции (на
остатках, статистический или обучаемый) строится отдельно. Прогноз задаёт
базовую линию, логика детекции работает на отклонениях от неё.

Важно: задача ALMA — определить **момент начала** аномалии, а не пометить
точки. Поэтому фундаментальная модель заменяет/дополняет **генератор
оценки** (роль PaAno-энкодера), а существующий слой детекции начала
(CUSUM + EMA + Optuna-пороги) **остаётся без изменений**. Это снижает риск
интеграции — меняется одно звено, контракт `DetectorScoreOutput` сохраняется.

## 4. Сопоставление моделей с задачей

### 4.1 Toto-2.0-2.5B — основной кандидат

Сильные стороны под задачу ALMA:

1. **Нативная многомерность.** Чередующиеся слои внимания по оси времени и
   по оси переменных моделируют совместную динамику каналов телеметрии
   (давление, нагрузка, расходы). Для `salt` с многоканальной ветвью это
   прямое попадание — не нужно прогнозировать каждый канал отдельно.
2. **Доменная близость.** Модель обучена Datadog для метрик наблюдаемости;
   бенчмарк BOOM — это промышленная телеметрия, ближайший аналог скважинных
   данных среди публичных корпусов.
3. **Вероятностная голова** (pinball loss, квантили) — готовый источник
   калиброванной оценки отклонения.
4. **Лёгкость.** 2.5 млрд параметров, ~9 ГБ fp32 (около 5 ГБ в bf16),
   ~36 мс на прогноз горизонта 1024 на A100. Спокойно помещается на одну
   A100-40GB, оставляя место для пакетной обработки всех скважин.
5. Причинный декодер совместим со стриминговым контрактом `edge_hold`.

Вывод: **наиболее перспособная модель для прямой интеграции в детектор.**

### 4.2 Timer-S1 — вторичный кандидат

- Вход одномерный — `(batch, lookback)`. Многоканальные признаки `salt`
  пришлось бы прогонять поканально, теряя межканальные зависимости. Менее
  естественно, чем Toto.
- 8.3 млрд параметров MoE, требование ≥40 ГБ VRAM — занимает A100-40GB
  целиком, конкурирует за GPU с тренировками PaAno.
- Главное преимущество — **контекст 11.5К точек**. Это полезно для `pritok`:
  на сетке 5–10 мин это десятки суток истории, что даёт длинный тренд для
  выявления медленного притока.

Вывод: держать как **сравнительный/резервный** вариант, прежде всего для
длинногоризонтного прогноза по `pritok`. Не основная ставка.

### 4.3 Thoth-30B — слой объяснения, не детектор

Thoth не детектирует и не прогнозирует — он **рассуждает** о ряде на
естественном языке. Применение в ALMA:

- **Постфактум-объяснение** в HTML-отчётах: по окну вокруг найденного
  начала аномалии Thoth формирует диагностический текст
  («резкое падение давления, характерное для негерметичности»).
- **Триаж/приоритизация** для эксперта.

Ограничения:
- 30 млрд параметров — нужен мультиGPU или квантизация для инференса;
- качество **русскоязычного** вывода не гарантировано — а отчёты ALMA
  обязаны быть строго на русском без англоязычного жаргона;
- строго **вне цикла детекции** — иначе непредсказуемость LLM попадёт в
  метрики.

Вывод: возможный **офлайн-помощник для отчётного слоя**, не приоритет.
Перед внедрением — отдельная проверка качества русского языка.

### 4.4 Альтернативный класс — модели именно для детекции аномалий

Помимо прогнозистов, в 2026 году появились фундаментальные модели,
обученные **непосредственно детекции аномалий** (zero-shot TSAD):

- **TimeRCD** (ICML 2026, *«Towards Foundation Models for Zero-Shot Time
  Series Anomaly Detection»*). Парадигма Relative Context Discrepancy:
  модель обучена не восстанавливать вход, а **сравнивать запрос с
  окружающим контекстом** и выявлять контекстные сдвиги. Авторы прямо
  критикуют детекторы на восстановлении — они «запоминают статические
  паттерны и пропускают тонкие аномалии в новых доменах». Это важный
  сигнал для ALMA: текущий PaAno — именно реконструкционный детектор, и
  TimeRCD заявлен как превосходящий такой класс в zero-shot.
- **MOMENT** — лёгкая фундаментальная модель (на базе T5), штатно
  поддерживающая детекцию аномалий, классификацию и импутацию помимо
  прогноза; пригодна для zero-shot и дообучения.

Эти модели стоит держать в поле зрения как **прямую альтернативу
PaAno-энкодеру** (а не только надстройку на прогнозе). Но их зрелость и
доменная переносимость на скважинные данные требуют проверки тем же
бенчмарком, что и Toto.

## 5. Риски и ограничения

1. **Доменный разрыв.** Модели предобучены на общих корпусах (LOTSA,
   Chronos, BOOM), а не на давлении нефтяных скважин. Zero-shot прогноз
   может быть приемлемым, но пороги аномальности всё равно требуют
   калибровки на наших скважинах — слой Optuna сохраняется обязательно.
2. **Прогнозист ≠ детектор.** Детектор на остатках надо строить и
   валидировать отдельно; «бесплатной» детекции не будет.
3. **Производные признаки `salt`.** Признаки мягкого датчика generic-модель
   прогнозирует плохо — физическую ветвь `salt` сохранять.
4. **Дисциплина train/test.** Любой дообучение — только на обучающих
   скважинах, как и текущие Optuna-пороги. Иначе утечка в тест.
5. **Офлайн-развёртывание.** Веса скачиваются один раз и кэшируются на
   сервере (офлайн-first архитектура проекта). Зафиксировать версии весов
   и `transformers` в `uv`-окружении.
6. **Свежесть моделей.** Работы марта 2026 — нестабильные API; ожидать
   правок `trust_remote_code`-кода при обновлении.

## 6. Предлагаемые сценарии интеграции

### Сценарий A — новый детектор на прогнозе (низкий риск, основной)

Добавить детектор `toto_global` рядом с `paano_global`, как отдельный ключ:

- обёртка Toto-2.0-2.5B как редактируемая зависимость в `alma_service/`
  (паттерн модульного ядра проекта);
- многомерный прогноз → квантильный остаток → оценка → существующий слой
  детекции начала;
- выход в контракте `DetectorScoreOutput` (primary / components / detail) —
  без изменений downstream-кода.

### Сценарий B — ансамбль (среднесрочно)

Слить в доменном слое решения две оценки:
- PaAno — новизна восстановления (что модель «не видела»);
- Toto — отклонение прогноза (что физически «не должно было произойти»).

Это разные режимы отказа; ансамбль должен повысить полноту. Доменный слой
уже сплавляет физические ветви — TSFM-ветвь добавляется тем же механизмом.

### Сценарий C — слой объяснения (опционально)

Thoth генерирует русскоязычный диагностический разбор для HTML-отчёта по
окну вокруг найденного начала. Строго постфактум.

## 7. План проверки

1. **Фаза 0.** Обернуть Toto-2.0-2.5B в модуль `alma_service`; реализовать
   многомерный прогноз → скорер остатков с контрактом `DetectorScoreOutput`.
   Закрепить веса и версии в серверном `uv`-окружении.
2. **Фаза 1.** Zero-shot бенчмарк `toto_global` на train/test скважинах;
   сравнение метрик начала (`scripts/evaluation/evaluate_onset_metrics.py`)
   с `paano_global`.
3. **Фаза 2.** При значимом доменном разрыве — лёгкое дообучение Toto
   только на обучающих скважинах.
4. **Фаза 3.** Ансамблевое слияние Toto + PaAno в доменном слое решения.
5. **Фаза 4** (опц.). Слой объяснения Thoth в отчётах; отдельная проверка
   качества русского языка.

Все длинные прогоны — на сервере `a100` через `tmux`, GPU 1–5.

## 8. Итог

- **Toto-2.0-2.5B** — лучший кандидат: многомерность, доменная близость к
  промышленной телеметрии, вероятностный выход, малый вес. Рекомендуется
  как новый детектор `toto_global` и далее как ветвь ансамбля.
- **Timer-S1** — резерв для длинногоризонтного прогноза `pritok`;
  одномерность и тяжесть снижают приоритет.
- **Thoth-30B** — не детектор; потенциальный офлайн-слой объяснения для
  отчётов, требует проверки русского языка.
- **TimeRCD / MOMENT** — отдельный класс моделей именно под детекцию
  аномалий; стоит включить в сравнительный бенчмарк как прямую
  альтернативу реконструкционному PaAno-энкодеру.
- Во всех сценариях слой детекции начала (CUSUM/EMA/Optuna) и физические
  ветви сохраняются — фундаментальная модель заменяет только генератор
  оценки, что делает интеграцию инкрементальной и низкорисковой.

## 9. Журнал экспериментов

### 9.1 TimeRCD — zero-shot проба на данных ALMA (2026-05-22)

**Что сделано.** На сервере `a100` поднята модель **TimeRCD** (репозиторий
`thu-sail-lab/Time-RCD`, ветка `tsb-ad-integration`; статья arXiv 2509.21190).
Окружение — отдельный `uv`-venv (Python 3.13, torch 2.11.0+cu130), веса с
HuggingFace (`pretrain_checkpoint_best_uni.pth` и `..._multi.pth`, по ~445 МБ —
модель порядка 110 млн параметров). Smoke-тест на синтетике пройден: вставной
блок аномалии получил оценку 1.0 против фона 0.006.

Прогон zero-shot (без дообучения) на трёх размеченных скважинах — по одной на
тип аномалии. Метрика — поточечный ROC-AUC оценки против размеченного
интервала; onset — первый выход вероятности за порог 0.5.

| Скважина | Тип | TimeRCD одноканальный (давление) | TimeRCD многомерный (26–27 кан.) | TimeRCD многомерный (top-7) | paano_global (onset) |
|---|---|---|---|---|---|
| 172г | negermet | **AUC 0.992**, onset +5.2 ч | AUC 0.663 | AUC 0.824 | +0.0 ч |
| 1062 | pritok | AUC 0.357, onset −286 ч | AUC 0.542 | AUC 0.562 | +1.8 ч |
| 149г | salt | AUC 0.860, onset −402 ч | AUC 0.693 | AUC 0.661 | +1.8 ч |

**Выводы.**

1. **Резкие аномалии — сильный результат.** На негерметичности по одному
   каналу давления TimeRCD zero-shot даёт почти идеальное точечное разделение
   (AUC 0.992). Это подтверждает дизайн парадигмы RCD: модель ловит резкие
   контекстные сдвиги между соседними окнами.
2. **Многомерный вход вредит.** Подача всех 26–27 каналов размывает сигнал
   (AUC 0.66). Сокращение до схемы top-7 частично спасает негерметичность
   (0.82), но не приток и не соль. Одноканальное давление везде превосходит
   многомерный режим. Multi-чекпойнт без жёсткой канальной селекции
   непригоден — это согласуется с наблюдением о просадке на 7-канальной схеме
   из `docs/ALMA_важность_признаков_paano_global.md`.
3. **Приток — принципиальный провал** (AUC < 0.5, хуже случайного). Медленный
   тренд притока не создаёт резкого контекстного сдвига, на который обучен
   TimeRCD. Это ограничение самой RCD-парадигмы, а не вопрос настройки.
4. **Onset — слабое место.** TimeRCD выдаёт поточечную вероятность, но без
   onset-логики наивный порог 0.5 срабатывает на сотни часов раньше реального
   начала (приток/соль) либо на 5 ч позже (негерметичность). paano_global со
   слоем CUSUM/EMA даёт +0.0…+1.8 ч. Это прямое подтверждение тезиса из
   разделов 3 и 7: фундаментальная модель даёт оценку, а onset-слой обязан
   остаться.

**Рекомендации по итогам пробы.**

- TimeRCD имеет смысл как **дополнительная ветвь для резких аномалий
  (негерметичность)**: одноканальная оценка давления, поданная в существующий
  onset-слой ALMA вместо/в дополнение к PaAno. AUC 0.99 — весомый сигнал.
- Для **притока TimeRCD не применим** — оставить трендовую ветвь paano_global.
- Многоканальный режим без канальной селекции использовать нельзя; даже top-7
  не догоняет одноканальный.
- **Следующий шаг:** подать TimeRCD-оценку (одноканальную, давление) в
  onset-слой ALMA и прогнать onset-метрики по всем скважинам негерметичности,
  сравнив с paano_global по hit-rate и смещению начала.

**Оговорки.** 3 скважины — это smoke-проба, не бенчмарк; нужен полный прогон.
Отрицательные смещения onset (−286/−402 ч) — артефакт сырого порога 0.5; может
быть как ранним сигналом, так и ложным срабатыванием в пред-аномальной зоне,
вопрос снимается onset-слоем. Размеченные интервалы грубые (часы), TimeRCD
оценивает поточечно — AUC слегка занижен.

**Артефакты.** Сервер: `/root/scratch/Time-RCD/` (репозиторий, веса,
`smoke_test.py`, `alma_eval.py`, `alma_eval_top7.py`). Это scratch-каталог вне
git, на источник правды репозитория не влияет.

### 9.2 Toto-2.0-2.5B — zero-shot проба на данных ALMA (2026-05-22)

**Что сделано.** На сервере `a100` поднята модель **Toto-2.0-2.5B** (Datadog,
пакет `toto-2`, статья arXiv 2605.20119; 2.45 млрд параметров — прогнозист
телеметрии наблюдаемости). Отдельный `uv`-venv. Поскольку Toto — прогнозист,
а не детектор, оценка аномальности построена как нормированный остаток
прогноза: `|факт − медиана| / (q0.9 − q0.1)`. Проверены две схемы:

- **скользящая** — контекст 512 точек, горизонт 64, переякоривание на реальные
  данные каждые 64 точки (методически корректная, причинная);
- **длинногоризонтная от фиксированной нормы** — контекст = первые 512 точек
  скважины, прогноз — весь остаток ряда одним вызовом.

Те же 3 размеченные скважины, что в 9.1.

**Скользящая схема (корректная):**

| Скважина | Тип | Toto одноканальный (давление) | Toto многомерный (max по каналам) |
|---|---|---|---|
| 172г | negermet | **AUC 0.915**, onset **+0.2 ч** | AUC 0.598 |
| 1062 | pritok | AUC 0.565 | AUC 0.514 |
| 149г | salt | AUC 0.518 | AUC 0.500 |

**Длинногоризонтная схема:** AUC 1.000 / 1.000 / 0.998 — **результат признан
невалидным.** Контрольный прогон на 5 чисто нормальных скважинах `norm_work`
(без аномалий) показал: остаток прогноза компаундится с дальностью горизонта
сам по себе — ранняя половина горизонта даёт средний остаток 7–16, поздняя
22–35 на скважинах **без аномалий**. Так как размеченные интервалы лежат в
хвосте окна данных, любой растущий со временем скор тривиально даёт AUC ≈ 1.0.
Это артефакт конфаундинга «аномалия в хвосте + остаток растёт с горизонтом»,
а не детекция.

**Выводы.**

1. **Резкие аномалии — работает.** На негерметичности корректная скользящая
   схема даёт AUC 0.915 и, главное, **onset +0.2 ч** — точнее, чем TimeRCD
   (+5.2 ч), почти вровень с paano_global (+0.0 ч). Прогнозный остаток ловит
   резкое падение давления сразу.
2. **Постепенные аномалии — провал** (приток, соль: AUC ≈ 0.5). Причина
   фундаментальна: при скользящем прогнозе медленный дрейф впитывается в
   контекст и становится предсказуемым → остаток не растёт.
3. **Длинногоризонтная схема не спасает.** Остаток прогноза компаундится с
   горизонтом независимо от наличия аномалии. Сырой остаток непригоден без
   калибровки базового уровня по дальности горизонта.
4. **Многоканальный режим** (агрегация max по каналам) — шум, AUC ≈ 0.5–0.6;
   как и у TimeRCD, многоканальность без аккуратной агрегации не работает.

**Сравнение трёх подходов на негерметичности (скважина 172г):**

| Подход | AUC | onset |
|---|---|---|
| TimeRCD одноканальный (zero-shot) | 0.992 | +5.2 ч |
| Toto скользящий одноканальный (zero-shot) | 0.915 | **+0.2 ч** |
| paano_global (рабочий детектор) | — | +0.0 ч |

TimeRCD точнее разделяет точки, Toto точнее ловит момент начала.

**Итог по zero-shot фундаментальным моделям.**

- Ни TimeRCD, ни Toto **не решают приток** в zero-shot. Трендовую ветвь
  paano_global оставить безусловно.
- Для **негерметичности** работоспособны обе; Toto предпочтительнее по точности
  onset, TimeRCD — по точечному разделению.
- Чтобы фундаментальная модель заработала на **постепенных** аномалиях, нужна
  калибровка или дообучение: для Toto — дообучение на нормальной телеметрии
  ALMA (`norm_work`), чтобы прогнозная неопределённость соответствовала
  динамике скважин и компаундинг остатка на норме исчез; либо
  референс-нормированный скор (остаток сравнивать с ожидаемым на норме при том
  же горизонте). Datadog публикует референсный код дообучения Toto на одной
  GPU — это реалистичный следующий шаг.

**Оговорки.** 3 скважины — smoke-проба. AUC на размеченных интервалах
чувствителен к расположению аномалии в окне (см. разбор длинногоризонтной
схемы) — для строгой оценки нужен прогон на скважинах с аномалией не в хвосте
и на нормальных скважинах как контроль ложных срабатываний.

**Артефакты.** Сервер: `/root/scratch/toto/` (`smoke.py`, `alma_eval.py`,
`alma_longhorizon.py`, `fp_check.py`). Scratch-каталог вне git.

### 9.3 Дообучение Toto на нормальной телеметрии ALMA (2026-05-22)

**Что сделано.** Официальный рецепт дообучения Datadog существует только для
**Toto 1.0** (`Toto-Open-Base-1.0`, 151 млн параметров; у версии 2.5B
тренировочного кода в репозитории нет). Дообучил Toto 1.0 прогнозной целью
(pinball loss) на `norm_work` — 20 нормальных скважин, канал давления,
800 шагов, ~2.5 мин на одной A100, лучший val-loss 0.474. Затем сравнил
zero-shot и дообученную модель на тех же 3 скважинах + FP-проверка на 3
нормальных скважинах.

| Скважина | Тип | Скользящая AUC, zero-shot | Скользящая AUC, дообуч. | Длинногор. AUC, zero-shot | Длинногор. AUC, дообуч. |
|---|---|---|---|---|---|
| 172г | negermet | 0.907 | **0.932** | 1.000 | 0.998 |
| 1062 | pritok | 0.567 | 0.600 | 0.999 | **0.113** |
| 149г | salt | 0.556 | 0.645 | 0.974 | **0.150** |

FP-проверка — остаток прогноза на скважинах **без аномалий**:

| | zero-shot | дообученный |
|---|---|---|
| средний остаток | 0.15–0.59 | 0.02–0.10 |
| поздняя половина горизонта | ≈ ранней | **≈ 0.00** |

**Выводы.**

1. **Дообучение технически удалось.** На нормальных скважинах остаток прогноза
   упал практически до нуля (поздняя половина горизонта — 0.00): модель выучила
   нормальную динамику скважин. Проблема ложной калибровки из 9.2 устранена.
2. **Это вскрыло артефакт.** Длинногоризонтная AUC ≈ 1.0 у zero-shot была
   конфаундингом (остаток рос с горизонтом, аномалия — в хвосте окна). Как
   только дообучение убрало компаундинг, длинногоризонтная AUC для притока и
   соли **рухнула до 0.11–0.15** — хуже случайного. То есть оптимистичные 1.0
   из zero-shot были ложными, доверять им нельзя.
3. **Причина инверсии — события качества данных.** Размеченная «аномалия»
   притока 1062 по `quality_status` детектора paano_global — это `sensor_stuck`
   / `bad_data` (застывший датчик). Плоская линия тривиально прогнозируема →
   остаток в зоне «аномалии» МАЛ, а в нормальной зоне с реальной динамикой —
   велик → AUC инвертируется. Прогнозный остаток принципиально не ловит
   аномалии-«заморозки».
4. **Скользящая схема:** дообучение дало умеренный равномерный прирост
   (+0.02…+0.09 AUC), но приток и соль остались слабыми (~0.6). Негерметичность
   — 0.932.
5. **Соль** — не stuck-sensor, но канал давления её не отражает; соль требует
   многоканальной ветви (нагрузка/температура) — что и делает paano_global.

**Итог.** Дообучение Toto **не делает прогнозный детектор универсальным**. Оно
(а) чинит калибровку — устраняет ложные срабатывания на норме; (б) даёт честную
картину: forecast-residual — детектор резких аномалий (негерметичность) и не
более.

**Практические выводы для ALMA.**

- Дообученный Toto в скользящей схеме — кандидат в **дополнительную ветвь
  только для негерметичности** (AUC 0.932). Для притока и соли — нет.
- **Часть размеченных интервалов притока — это события качества данных**
  (`sensor_stuck`), а не аномалии динамики. Прогнозные модели для них
  неприменимы в принципе; их должен ловить слой качества данных — он в
  paano_global уже есть (`quality_status`). Это наблюдение стоит учесть при
  оценке любых детекторов на этих интервалах.
- Дообучение версии 2.5B не делалось (нет официального рецепта). По итогам
  пробы на 1.0 смысла в нём мало: прирост скользящей схемы маргинален, провал
  на притоке/соли — структурный.

**Артефакты.** Сервер: `/root/scratch/toto-repo/` (`ft_run.py`,
`ft_config.yaml`, `ft_eval.py`, `checkpoints/alma_norm_work/`). Вне git.

### 9.4 Базовые (не-глубокие) методы детекции — проба на данных ALMA (2026-05-22)

размеченной аномалии; окно 64 точки. Метрики — точечный ROC-AUC против
размеченного интервала и **контроль ложных тревог** на 3 нормальных скважинах
`norm_work`.

**Таблица 1 — точечный AUC на размеченных скважинах.**

| Isolation Forest | 0.939 | 1.000 | 0.977 |
| One-Class SVM | 0.999 | 1.000 | 0.967 |

**Таблица 2 — контроль ложных тревог.** Обучение на 1-й половине нормальной

**Выводы.**

1. **AUC обманчив.** На точечном AUC почти все базовые методы дают 0.98–1.0 —
   формально не хуже, а местами «лучше» paano_global (0.97–0.99). Но это
   ловушка.
2. **Контроль ложных тревог разоблачает.** На *чисто нормальных* скважинах те
   же методы помечают аномалией **21–94%** точек при идеале ≈ 1%. У наивных
   базовых методов нет контроля ложных срабатываний вообще.
3. **Причина.** Нормальная скважина естественно дрейфует со временем (смена
   режима, эволюция давления). Метод, обученный на ранней норме, видит позднюю
   норму как «другое» → аномалия. На размеченных скважинах аномалия удачно
   лежит в хвосте окна → высокий AUC возникает «по совпадению» механизма
   «позднее ≠ раннее». На нормальной скважине тот же механизм даёт поток
   ложных тревог.
4. **Это эмпирическое подтверждение урока TSB-AD** (раздел 3 обзора
   [обзор_методов_детекции_и_предсказания_аномалий.md](обзор_методов_детекции_и_предсказания_аномалий.md)):
   точечный AUC на нескольких очевидно-аномальных скважинах не различает
   методы; реальная проверка — контроль ложных срабатываний, и наивные
   базлайны её проваливают.
5. **Matrix Profile** — AUC 0.03–0.35, ниже случайного. Matrix Profile ищет
   **короткий редкий** «диссонанс»; аномалии ALMA — длинные устойчивые режимы
   (978–3513 точек). Длинная аномалия сама себе соседи → её MP-значение
   *низкое*, а более вариативная норма — высокое → инверсия. Matrix Profile —
   неподходящий инструмент для длительных аномалий.
6. **paano_global** — AUC 0.97–0.99, в той же зоне, что базлайны, но его
   ценность не в AUC. Референсная модель, маски стабильности,
   coverage-статусы, onset-слой существуют именно чтобы **не** срабатывать на
   нормальном дрейфе — ровно тот тест, который базлайны провалили.

**Итог.** Тезис «базовые методы нельзя списывать со счёта» верен, но **только
если** они включают обработку дрейфа/режима (скользящее переобучение,
детренд, режимную нормализацию, сегментацию по точкам разладки). Наивные
учебные версии без этого непригодны: на лёгком AUC-бенчмарке выглядят
отлично, на нормальных данных дают 20–94% ложных тревог. paano_global несёт
ровно ту машинерию, которой наивным базлайнам не хватает.

**Оговорки.** Точечный AUC чувствителен к расположению аномалии в хвосте окна
(как в 9.2/9.3). Метрика ложных тревог (порог 99-го перцентиля) строгая, но
разрыв 1% → 21–94% однозначен. One-Class SVM выдаёт знаковые скоры —
отношение аном/фон неинформативно, но AUC (ранговый) корректен.

**Артефакты.** Сервер: `/root/scratch/toto/` (`baselines_eval.py`,
`baselines_fp.py`). Вне git.

### 9.5 Улучшение базовых методов — проба на данных ALMA (2026-05-22)

**Выводы.**

1. **Главное улучшение достигнуто.** Ложные тревоги упали с 21–94% (наивные
   базлайны) до **1–6%**. Диагноз подтверждён: проблема была в глобальном
   эталоне и чувствительности к уровню; скользящий эталон, центрирование окон
   и приращения её чинят.
2. **Бесплатного обеда нет.** Агрессивное подавление дрейфа (скользящий z,
   EWMA-z, приращения) убивает и медленные аномалии: на притоке и соли эти
   методы ≈ случайны (0.50–0.60) — медленный тренд внутри скользящего окна
   выглядит локально нормально (тот же провал, что у скользящего Toto в 9.2).
   Хороши только для резких аномалий.
3. **Компромисс — центрированные окна.** IForest на центрированных окнах:
   ложные тревоги 6% (было 65–89%), при этом AUC негерметичности 0.995 и
   притока 0.964 — центрирование убирает дрейф уровня, но сохраняет
   форму/наклон, поэтому аномальный тренд притока остаётся виден. Лучший из
   улучшенных вариантов.
4. **Соль слаба у всех** (0.49–0.63) — это не проблема метода, а проблема
   канала: солеотложение не отражается в давлении на приёме. Нужен
   многоканальный вход (нагрузка, температура) — что и делает paano_global.
   Приращения вообще уничтожают сигнал соли (0.22) — дифференцирование убирает
   медленную компоненту.

**Итог — как улучшать базовые методы.**

- **(а) Обработка дрейфа обязательна.** Лучший дешёвый приём — центрированные
  окна (одна строка: вычесть среднее окна): ложные тревоги 65–89% → 6%, AUC
  держится.
- **(б) Нужны две ветви.** Глобальное подавление дрейфа отнимает медленные
  аномалии; быстрая ветвь (центрированные окна / скользящий z) — для резких,
  отдельная трендовая ветвь — для медленных (приток).
- **(в) Для соли — многоканальный вход** (давление + нагрузка + температура).
- **(г) Калиброванный порог.** Сырой скор подавать в onset-слой ALMA
  (CUSUM/EMA), а не в наивный перцентиль.
- Сумма (а)–(г) — это по сути архитектура **paano_global** (две шкалы +
  многоканальность + доменный слой + onset-слой). «Улучшение базовых методов»,
  доведённое до рабочего состояния, сходится к тому, что paano_global уже
  имеет. Разумный практический максимум для лёгкого базлайна — **IForest на
  центрированных многоканальных окнах + onset-слой**: сильный дешёвый ориентир
  для бенчмарка, но не замена paano_global.

**Артефакты.** Сервер: `/root/scratch/toto/baselines_improved.py`. Вне git.

### 9.6 Полный рецепт улучшения базовых методов — реализация и проверка (2026-05-22)

**Выводы.**

1. **Рецепт работает целиком.** Две ветви закрывают оба режима: ветвь-форма
   ловит резкое (негерметичность 0.988), ветвь-тренд — медленное (приток
   0.980, соль 0.888). По отдельности каждая ветвь проваливает «чужой» тип
   (форма на притоке 0.570, на соли 0.445) — именно объединение по максимуму
   даёт все три: 0.98 / 0.98 / 0.91.
2. **Соль наконец поднялась** — с 0.63 (одноканально, 9.5) до **0.91**
   (многоканальный вход + трендовая ветвь). Пункт 3 рецепта подтверждён.
3. **Ложные тревоги ~3%** против 21–94% у наивных базлайнов — уровень
   практической пригодности; 2 из 3 нормальных скважин < 1.5%.
4. **Остаточная проблема.** На скважине 129л с сильным естественным дрейфом
   ветвь-тренд даёт 7.6% ложных. Трендовый детектор по построению чувствителен
   к скорости дрейфа; на скважине с быстрой нормальной эволюцией он
   срабатывает. Фикс — калибровать трендовый порог по **популяции** нормальных
   скважин (не только по первой половине самой скважины) и/или сегментировать
   референс по точкам разладки.

**Итог.** Полный рецепт 9.5 доводит лёгкий базлайн до AUC ≈ 0.96 и ложных
тревог ≈ 3% — практически вровень с paano_global (0.97–0.99) по AUC при
приемлемом контроле ложных срабатываний. Это подтверждает вывод 9.5:
«улучшение базовых методов», доведённое до конца, **сходится к структуре
paano_global** (две шкалы + многоканальность + калибровка). Лёгкий базлайн
годится как сильный дешёвый ориентир для бенчмарка; paano_global сохраняет
преимущество в точности onset, coverage-статусах и обработке качества данных
— того, что этим тестом не измеряется.
